# Reporthole — Frontend

Next.js mobile-first web app for the Reporthole civic road-incident reporting platform. Civilians authenticate, capture or upload a photo, select an issue category, and submit reports. The app receives real-time status updates over SSE when a report is confirmed or progresses through the municipal workflow.

---

## Tech stack

| Layer | Technology |
|-------|-----------|
| Framework | Next.js (App Router) |

## Quick start

**Prerequisites:** Node.js 20 LTS, npm (bundled with Node), backend running at `http://localhost:8080/api`.

```bash
cd reporthole-fe
npm install
cp .env.example .env.local          # fill in NEXT_PUBLIC_API_URL
npm run dev                          # http://localhost:3000
```

See the backend [README](../reporthole-be/README.md) and [`docs/DEV_SETUP.md`](../reporthole-be/docs/DEV_SETUP.md) to get the API server running first.

For the full Docker stack (FE + BE + DB) see [`docs/DOCKER_SETUP.md`](../reporthole-be/docs/DOCKER_SETUP.md).

## orval API client

The frontend never writes manual `fetch` or `axios` calls for backend endpoints. All API calls go through typed hooks generated by orval from the backend's live OpenAPI spec.

**Regenerate after any backend change:**
```bash
# backend must be running
npm run generate:api
```

Generated files live in `app/api/generated/` — do not edit them. Commit after regenerating so teammates get updated types.

**Using generated hooks:**
```ts
// GET → query hook
import { useGetMyIncidents } from "@/app/api/generated/incidents/incidents";
const { data, isLoading } = useGetMyIncidents();

// POST → mutation hook
import { useCreateIncident } from "@/app/api/generated/incidents/incidents";
const { mutateAsync: submit } = useCreateIncident();
```

All request/response types come from `@/app/api/generated/openAPIDefinition.schemas`.

## Auth

JWT is stored in a cookie named `reporthole_token`. The Axios instance in `lib/axios.ts` reads the cookie and attaches it as a `Bearer` token on every request. `middleware.ts` guards protected routes — unauthenticated users are redirected to `/login`.

## Geolocation note

The browser Geolocation API requires a secure context (HTTPS). `localhost` is exempt but any LAN IP is not. Mobile testing over a local network IP without HTTPS will result in geolocation silently failing.
